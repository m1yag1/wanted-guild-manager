Create and track sign ups for Wanted Guild PvX events in Throne and Liberty,
from Discord slash commands.

The plan and its reasons are in [docs/decisions](docs/decisions).

## Requirements

- [uv](https://docs.astral.sh/uv/) for Python packages
- [invoke](https://www.pyinvoke.org/) for tasks
- [git-cliff](https://git-cliff.org/) for the changelog

## Setup

```bash
uv sync
uv run pre-commit install --hook-type pre-commit --hook-type commit-msg --hook-type pre-push
cp .env.example .env   # then fill in the values
```

## The backend

A Litestar app served by Granian (ADR 0010). It follows the Litestar agent
skills in `.claude/skills/`, and the app is always built by `create_app()`.

```bash
uv run litestar --app wgm.server.app:create_app run   # http://127.0.0.1:8000/ping
uv run pytest                                         # tests with the 100% coverage gate
uv run pre-commit run --all-files                     # ruff, mypy and file checks
```

Routes so far:

- `GET /ping` answers `{"message": "pong!"}`.
- `POST /discord/interactions` receives Discord interactions. It rejects any
  request without a valid Discord signature and answers Discord's PING.

## Tasks

```bash
uv run inv --list                              # all tasks
uv run inv github.apply-settings --dry-run     # repository settings, see .github/settings
```

## Staging droplet

Settings are in `deploy/droplet.toml`; the playbooks are in `deploy/ansible/`.
You need `doctl` logged in and the `wgm-do` SSH key (`~/.ssh/wgm_do`).

```bash
cp .env.example .env.staging          # fill in the staging Discord values
uv run inv droplet.up                 # create (if needed) and provision; prints the link
uv run inv deploy                     # build and deploy to staging
uv run inv status                     # service, version, /ping and certificate
uv run inv logs --since 30m           # app logs (--service nginx for nginx)
uv run inv deploy.rollback            # back to the previous release
uv run inv droplet.down               # delete the droplet (asks for its name)
```

## Layout

```text
src/wgm/
  server/          create_app() and plugins
  domain/<area>/   controllers, schemas and services for one area
  lib/             shared code, such as settings
tasks/             invoke tasks
deploy/            droplet settings and Ansible playbooks
tests/unit/        mirrors src/wgm
tests/fixtures/    shared pytest fixtures (plugins), with payloads in fixtures/data/
```

## Commits and releases

Commits follow [Conventional Commits](https://www.conventionalcommits.org/),
for example `feat(signup): block sign ups when an event is full`. A hook checks
each message. `git-cliff` builds `CHANGELOG.md` from them when we release.

The earlier static web prototype is kept under the git tag `web-prototype`.
